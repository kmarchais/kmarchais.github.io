I've been developing **Meshers**, a CPU tetrahedral meshing library written in
Rust with a Python API. Its first application is an optional meshing backend
for [Microgen](https://github.com/3MAH/microgen).

The aim is to get closer to the boundary, improve element quality and reduce
meshing time at a comparable element budget. A periodic Gyroid unit cell is a
useful first example: it has curved walls, narrow passages and opposite faces
that need to match.

Explore one actual Gyroid mesh generated by Meshers. Rotate it, expose the
interior tetrahedra, inspect element quality or highlight the periodic caps.
The plots below compare the two meshing routes on the same frozen specimen.

## One specimen, two meshing paths

The tested Microgen+MMG route samples the field on a VTK grid and clips the
solid, then runs the existing two-pass MMG pipeline. This is the actual default
route, using sampling resolution 20, not MMG applied to a Meshers seed.

Meshers constructs tetrahedra from the implicit field, using it for boundary
projection and quality improvement. Supported Python expressions compile to
native evaluation with derivatives; other supported fields can use NumPy
callbacks. No GPU is needed for meshing. Three.js is used here only to inspect
the saved output.

The specimen is a unit Gyroid sheet with offset 1.1. The native comparison uses
12 background cells per axis, without adaptation. Counts are close, rather than
identical: 10,832 tetrahedra for Meshers and 12,250 for Microgen+MMG. The native
budget was selected by count proximity before the repeated timing.

## Generation time and every requested quality statistic

These are medians from five interleaved measured pairs on an Apple M4 MacBook
Pro with one numerical thread, after one excluded warmup pair. Generation time
excludes independent audits, shared fixture preparation and FEA.

Quality is the same dimensionless MMG-normalized tetrahedron measure on both
sides, with one for a regular tetrahedron. Mean is the arithmetic mean over
cells. The percentiles and mean are calculated from the original Float64
coordinates and connectivity, not the display mesh.

Meshers improves the minimum, median, mean, p10 and p90 in this pair. MMG has a
slightly higher maximum. The maximum describes the best element; the minimum
and lower quantiles describe the weak tail. Reporting all six keeps that
difference visible.

The raw generation-time difference is substantial, but the comparison is not
an accuracy-qualified speedup. Both meshes miss the strict boundary target
described below.

## Periodicity is more than matching coordinates

Both outputs pass the recorded opposite-node and material-cap triangulation
checks at a coordinate tolerance of 1e-10.

Mesh coherence is checked separately. A matching pair of periodic
faces does not rule out conflicting tetrahedra elsewhere in the mesh. The MMG
output has four same-orientation shared-face conflicts; these remain in the original comparison data and are reported rather than repaired for the comparison.

## Geometry fidelity still limits this result

The study requires sampled two-sided boundary distance at most 0.002 unit-cell
lengths, absolute volume error at most 1%, minimum quality at least 0.1,
positive elements, coherent facets and complete applicable periodic matching.
The resource cap is 250,000 nodes and tetrahedra.

The count-selected Meshers mesh has sampled two-sided boundary error 0.007466.
The MMG mesh has reverse-only error at least 0.008461; its full audit stops
after quality, volume and facet rejection. That lower bound already exceeds
the boundary target. **Neither route passes every admission gate.**

The native recipe uses a loose internal geometry tolerance of 1.0 to measure
this coarse budget. That setting is recorded, not presented as an accuracy
guarantee. More accurate native selections exist at larger element counts;
those must be compared separately rather than substituted into these plots.
Sampled distances also remain estimates, not certified Hausdorff bounds.

This makes the next optimization question specific: retain the time and quality
advantages while improving boundary accuracy without a large increase in cells.
The complete study keeps the other geometries and FEA convergence questions in
scope. These software and mesh checks do not certify continuum accuracy.

## The optional Microgen integration

Existing calls keep their behavior:

```python
from microgen import Tpms
from microgen.shape.surface_functions import gyroid

shape = Tpms(gyroid, offset=1.1)
vtk_mesh = shape.generate_volume_mesh()
mmg_mesh = shape.generate_volume_mesh(backend="mmg", periodic=True)
meshers_mesh = shape.generate_volume_mesh(
    backend="meshers",
    cells=12,
    geometry_tolerance=1.0,  # Coarse comparison setting, not an accuracy guarantee.
    minimum_quality=0.1,
    optimize_passes=1,
    max_tetrahedra=250_000,
    periodic=(True, True, True),
)
```

The MMG selector calls the same VTK seed and existing remesher. It retains the
remesher's Boolean `periodic=True` default; bounded nonperiodic solids need
`periodic=False`. Meshers takes one periodic flag per axis. Its tetrahedra are
packaged as a PyVista data structure, without calling VTK's meshing algorithms
or MMG.

This code illustrates the candidate API. The frozen measurements use the study
builds and recipes linked below; future versions can produce different meshes.
The adapter currently covers implicit Shape objects, Cartesian TPMS and
spinodoids. Mapped domains and grid-sampled grading still need further work.
